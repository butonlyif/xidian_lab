# Stage-0 — t20f256-xd-ps-eval Skeleton Project

`stage0` is the minimal runnable project that the EvoVerse SDK (`evoverse new-project`) generates for [t20f256-xd-ps-eval](../../t20f256-xd-ps-eval.md): an LED blink design that occupies only the three skeleton signal classes — clock, reset and LED — to exercise the full "project generation → synthesis → place-and-route → programming → on-board observation" chain during onboarding.

## Hardware Resource Usage

| Signal | Direction | Pin | Level | On-board resource |
|---|---|---|---|---|
| `clk_50m` | in | H13 | 3.3 V LVTTL/LVCMOS | 50 MHz system clock |
| `arst_n` | in | A4 | 3.3 V LVTTL/LVCMOS | active-low reset button |
| `led_user` | out | T8 | 3.3 V LVTTL/LVCMOS | user LED |

All 7 involved IO banks (1A, 1B_1C, 1D_1E, 3A_3B_3C, 3D_3E, 4A, 4B) are at 3.3 V. Pins and levels come from automatic parsing of the board pin map, consistent with the stage-0 skeleton signals in [t20f256-xd-ps-eval.md](../../t20f256-xd-ps-eval.md).

## Design Notes

`rtl/top.v` (top module `t20f256_xd_ps_eval_stage0`) is purely synchronous single-domain logic:

- A 24-bit counter increments on the rising edge of `clk_50m` and is asynchronously cleared by `arst_n`;
- The counter MSB `cnt[23]` directly drives `led_user`, giving a blink period of about 0.34 s at 50 MHz.

No PLL and no other IP dependencies — the minimal workload for checking toolchain and board health.

## File List and Generation

```text
stage0/
├── rtl/top.v                          # skeleton RTL (auto-generated)
├── constraints/
│   ├── t20f256_xd_ps_eval_stage0.pins.isf   # pins and bank voltages (auto-generated)
│   └── t20f256_xd_ps_eval_stage0.sdc        # main clock constraint (auto-generated)
└── t20f256-xd-ps-eval-stage0.xml            # Efinity 2026.1 project (auto-generated)
```

All files are generated by the SDK from the board pin map; **do not edit them by hand**. The timing constraint declares only the main clock: `create_clock -name clk_50m -period 20.000 [get_ports clk_50m]`.

To change pins, modify the board pin map (`pinout/t20f256-xd-ps-eval.csv` and its upstream definitions) and regenerate; to carry real functionality, create a new jacket (see the structure of [marquee](../marquee/marquee.md)) instead of modifying stage0.

## Build and Programming

1. Open `t20f256-xd-ps-eval-stage0.xml` with Efinity 2026.1.
2. Run Synthesis → Place & Route → Generate Bitstream in order.
3. After programming and power-on, observing the user LED blinking at about a 0.34 s period means success; if the LED stays dark, use this project first to check the clock, reset polarity and LED pin mapping.
