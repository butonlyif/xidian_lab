知识 · 极性列的「假设」是什么意思

极性列写着「假设」的项（数码管段低电平点亮、位选高有效、拨码上拨 = 1、蜂鸣器高电平鸣）， 都是板卡文档没有写死的电气细节——本章末尾会把它们逐条写成设计决策。

可能 · 板上还有更多（本教程不展开）

板卡目录里同样定义了这些物料，留给后续迭代：VGA（19 管脚电阻梯 DAC）、 USB 串口（CH340N，N16/P16）、SPI Flash（W25Q32）、I2C EEPROM、 40-pin 扩展口上的 18 对 LVDS、JTAG（FT232HL）。

习惯

把「假设」写进设计决策

这一步在做什么：板卡文档没有写死的电气细节（数码管共阳/共阴、位选有效电平、拨码方向）， 在设计里必须显式声明，将来上板验证若不符，改一处即可。

本教程的做法是在规格包的 decisions.json 里各记一条（第 04 章会看到完整文件），例如：

{
  "id": "DEC-SEG-LOW-ACTIVE",
  "title": "段线低电平点亮（共阳段码表）",
  "decision": "seg_o 采用低有效段码（0→8'hC0 … 9→8'h90，dp 恒灭）",
  "rationale": "FJ3461AH 经电阻网络驱动，业界共阳惯例；上板若整段相反，把查表值按位取反即可（一处改动）",
  "status": "ACCEPTED"
}

四个假设各一条：段低有效、位选高有效、按键低有效、拨码上拨为 1。它们全部在集成后上板阶段验证。

✓ 四个假设已显式记录 · 待上板验证
知识 · 显式声明的收益

把假设写进 decisions.json 的好处是可追溯：上板验证若不符，改一处即可—— 比如整段极性相反，把查表值按位取反就行（上方 rationale 里写的就是这一处改动）。
