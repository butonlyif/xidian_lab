CHAPTER 09

增量二：按键消抖与拨码采样

第二个并行意图：两级同步 + 20 ms 稳定计数，「19 拒 20 收」的阈值边界。

知识 · 按键为什么需要消抖

机械按键按下瞬间触点会弹跳，电平在几毫秒内反复翻转，直接采样会把一次按压数成好几次。 消抖的做法：检测到电平变化后启动稳定计数，只有保持够久（本章阈值 100 万拍 = 20 ms@50MHz）才接受新电平， 并在接受拍发恰好一个单周期脉冲。

板级异步输入进时钟域之前还要先过两级同步器防亚稳态——这就是 REQ-3 的来源。

STEP 2

规格要点：把「边界」写成可判定的条款

这一步在做什么：消抖的语义核心是阈值——低电平保持「少于阈值」不触发、「达到阈值」触发。 这两条必须分别成为需求与场景，否则仿真无法证明边界正确。

条款内容
REQ-1稳定保持 DEBOUNCE_CYCLES（默认 100 万拍 = 20 ms@50MHz）后，在达成拍产生恰好一个单周期脉冲
REQ-2持续低电平小于阈值的毛刺零脉冲——含「阈值−1 拍」这个最长拒判毛刺
REQ-3拨码每位经 2 级同步后第 2 拍起跟随，10 位全覆盖
REQ-4复位期间脉冲与拨码输出全零
知识 · mat-board-io 新形态

材料契约这里出现一个新形态：mat-board-io 描述「顶层将把按键/拨码管脚扇出为总线」， 端口方向是 output（逻辑视图），用来承接模块的两个 data 输入——这样系统连接 u_stage0_top.btn_bus_o → u_input_ctrl.btn_i 就能满足控制面的方向/宽度/连接性检查。

知识 · 为什么「阈值−1」也要测

阈值条款最怕「差一」错误：计数器多比一拍或少比一拍，边界行为就整个反了。 把「阈值−1 拍」（最长应拒判的毛刺）和「恰阈值」各写成一个场景， 仿真才能证明分界线不偏不倚——这就是「19 拒 20 收」的由来。

STEP 3

RTL：两级同步 + 稳定计数 + 按下沿脉冲

// 消抖核心（V2001 兼容；词法安全写法）
(* ASYNC_REG = "TRUE" *) reg [NUM_BTNS-1:0] btn_sync1, btn_sync2;   // 两级同步链
wire differ   = (btn_sync2 != btn_stable);        // 与已接受电平比较
wire deb_done = (db_cnt == (DEBOUNCE_CYCLES - 1));
wire accept   = differ && deb_done;               // 拆成两行：避免 differ db_cnt ( 的词法邻接
wire [NUM_BTNS-1:0] press_edge = btn_stable & ~btn_sync2;
...
pulse_r <= accept ? press_edge : {NUM_BTNS{1'b0}}; // 仅"释放→按下"的接受拍出脉冲
看什么accept 被刻意拆成两行、press_edge 用了中间线—— 都是为了躲开词法器的「词法邻接」陷阱，报错原文与修法见右栏修复卡。
修复 · 词法邻接陷阱

accept 那行——第一次写成单行 differ && db_cnt == (N-1)， 词法器把比较括号贴给 db_cnt，报了：

referenced missing module differ

修法：把比较拆成 deb_done 单独一行，accept = differ && deb_done 成两行， 避免词法邻接；press_edge 中间线也是为了躲开三元表达式里的 accept ? ( 邻接。

知识 · 两级同步器

btn_sync1 → btn_sync2 两级触发器带 (* ASYNC_REG = "TRUE" *) 属性， 让异步按键电平在被消抖计数逻辑使用之前先对齐系统时钟——第一级可能进入亚稳态，第二级输出基本稳定。 没有这两拍，后面的稳定计数毫无意义；拨码通道的 REQ-3 用的也是同一招。

STEP 4

testbench：毛刺三连与阈值精确性

这一步在做什么：把 REQ-2 的边界语义做成三类激励（短、中、阈值−1），再跟一次「恰阈值」按压证明分界线不偏不倚。

DEB = 20（提速参数；上板默认 1_000_000）
glitch(btn0, 3)    // 短毛刺 3 拍       → 0 脉冲
glitch(btn1, 2)    // 中毛刺 DEB/10    → 0 脉冲
glitch(btn2, 19)   // 边界毛刺 DEB-1   → 0 脉冲   ← 阈值左侧
press (btn2, 20)   // 恰阈值按压        → 1 脉冲   ← 阈值右侧
TB-RESULT.PASS (pulses=4 sw_events=10)      # 3 次按压 + 1 次阈值按压 = 4 脉冲；10 位拨码全跟随

知识 · 提速参数 DEB 怎么读

上板默认 DEBOUNCE_CYCLES = 1_000_000（100 万拍 = 20 ms@50MHz），仿真等比缩成 DEB = 20： 短毛刺 3 拍、中毛刺 DEB/10 = 2 拍、边界毛刺 DEB−1 = 19 拍（阈值左侧最长拒判）、 恰阈值按压 20 拍（阈值右侧）。四条激励把「19 拒 20 收」钉死，比例语义与上板完全一致。

STEP 5

一个值得记住的控制面行为

翻车实录两个意图的规格先后 APPROVED 后，先仿真 btn-switch 一切顺利； 轮到 seg-counter 却报 SPEC_IDENTITY_MISMATCH。对 seg 的密封包重走一次 spec.draft + spec.approve 后仿真通过——根因见右栏。
⚠ 多意图并行时「当前生效规格」只认最新一条 APPROVED
修复 · SPEC_IDENTITY_MISMATCH

报错原文：

SPEC_IDENTITY_MISMATCH: digest does not match the requested specDigest

修法：对 seg 的密封包再走一次 spec.draft + spec.approve （产生同 digest 的 SPEC-004 成为最新），然后仿真通过。

知识 · 解析顺序只认最新

verification.simulate 在解析「当前生效规格」时只认最新一条 APPROVED 记录—— 先仿真 btn-switch 一切顺利只是因为它恰是最新。这类「多意图并行时的解析顺序」行为已如实记录在第 11 章手册里。
