CHAPTER 12

下一步：RISC-V

纯 RTL 之后，这块板还能走多远——串口、软核、软硬协同的路线图。

本章目标

盘点已具备的跳板（串口/拨码/外设）与 SDK 已提供的软件能力，画出一条从「逻辑跑马灯」到「软件可编程」的迭代路径。

为什么现在才谈软核

本教程刻意先走完纯 RTL：控制面的可靠链路（意图→规格→候选→仿真→晋级）对硬件逻辑与软硬协同设计是同一套。 先把这条链在纯逻辑上练熟，加入处理器后的每一步（总线外设、寄存器映射、软件测试）才有可信的落点。

板上现成的跳板

资源在本教程中的状态下一步用法
USB 串口（CH340N，N16/P16）未使用软核的 stdout/命令行——第一个软件程序的落点
拨码 SW1..10已采样未接负载软核的 GPIO 输入：读拨码改跑马灯方向/速度（正好补上第 10 章留的口）
数码管 / LED / 蜂鸣器纯 RTL 驱动映射成软核的内存外设：软件写寄存器即显示
SPI Flash（W25Q32）未使用固化比特流 / 存软核程序镜像
VGA（19 管脚电阻梯）未使用帧缓冲显示（进阶）

SDK 已经准备好的软件能力

  • RISC-V Sapphire SoC：通过 Efinity 原生 IP Configuration Wizard 配置多 Tab GUI，一键 Sync 回工程；
  • RISC-V 工具链管理（xPack RISC-V GCC）：SoC 创建、App 构建、BSP 生成；
  • 软硬契约：EXECUTABLE_2_0 的 hardware-software contract + 软件规格 + 软件测试， 走与本章完全相同的控制面动作推进；
  • GDB 调试与 Workbench 的 Software 页签。

建议的三个迭代

迭代 A

软核 Hello World

新意图：例化最小 Sapphire SoC + 串口外设，软件侧打印启动横幅。验收：串口助手看到输出， 软件测试在控制面拿到 host 级 PASS 证据。

迭代 B

拨码 + 数码管外设化

把 input_ctrl 的拨码通道与 seg_display8 挂到软核总线（寄存器映射）。 验收：软件读拨码寄存器、写显示寄存器；本教程的三个 RTL 模块全部变成可编程外设。

迭代 C

固化管理

比特流与软件镜像写入 SPI Flash，上电自启动。验收：断电重启后无需主机参与即可运行。

结语

回顾这条链：一句话建工程 → 骨架编译体检 → 意图/等级/规格的受管推进 → 候选冻结与真实仿真 → 原生编译与约束复验 → 并行增量与隔离 worktree → 集成与最终编译。每一份报告、每一条报错都来自真实运行， 它们合起来就是这块板子从零到产品化的最短路径。剩下的，交给你的下一个意图。
